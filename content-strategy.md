# IGDown Content Strategy

## Editorial principle

Publish content because it helps a public-link downloader user complete a task or understand a limitation. Do not create one page per keyword spelling. Google says its systems prioritize helpful, reliable, people-first content and explicitly warns against producing many automated pages mainly to attract search visits. Source: [Google people-first content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

## Audience and jobs

1. A repeat user who already has a public URL and wants the tool immediately.
2. A first-time user who needs copy-link and save-location instructions.
3. A user diagnosing private, malformed, deleted, restricted, or partially extracted media.
4. A creator or rightsholder checking privacy, permissions, or reporting options.
5. A device-specific user confused by Android Downloads, iOS Files, or browser policy.

## Homepage content model

The tool, H1, short explanation, and input stay above the comprehensive guide. The guide covers video, reels, photos, carousels, steps, public/private boundaries, unsupported Stories/profile pictures, source quality, MP4, Android, iPhone, desktop browsers, security, privacy, copyright, troubleshooting, and visible FAQs. This is deliberately useful prose—not repeated keyword blocks.

## Page quality standard

Every new indexable page must include:

- a single distinct user problem and primary intent;
- evidence from real product behavior or controlled testing;
- a descriptive title/H1 without superlatives or unsupported claims;
- visible limitations and failure modes;
- at least one contextual link to the right tool and one to supporting help;
- unique examples, headings, FAQs, and metadata;
- an owner and genuine review date;
- a merge/redirect decision if an existing page already answers the intent.

Word count is not an acceptance criterion. Completeness, accuracy, originality, and task success are.

## Unsupported topics

Stories, Close Friends, private posts, direct messages, and profile-picture lookup are not active SEO clusters. The existing Story/profile paths are noindex capability notices. They become indexable only after reliable product support, updated tests, user-facing previews, policy review, and measured extraction success.

## Publishing workflow

1. Select topics from Search Console evidence or recurring support questions.
2. Write an intent brief and name the existing canonical parent.
3. Capture first-party screenshots/examples without third-party copyrighted media.
4. Draft, fact-check against source code and product behavior, and review rights/privacy wording.
5. Add metadata, schema only if eligible, internal links, and tests.
6. Publish, inspect, measure for at least 28 days, then improve or prune.
